# MarketFlow

A Django REST backend for a multi-vendor marketplace. Customers can buy from several shops in one checkout. Sellers manage their catalogs and shipments. Administrators review shop applications, manage categories, and monitor payments.

[Functional requirements](design/functional-requirements.md) · [Database ERD](design/erd.md) · [OpenAPI contract](design/openapi.json)

## Tech stack

| Area | Tools |
| --- | --- |
| Backend | Python 3.13, Django, Django REST Framework |
| Database | PostgreSQL 16, Django ORM, psycopg |
| Authentication | Simple JWT and role-based permissions |
| Local development | Docker, Docker Compose |
| API documentation | OpenAPI 3.1, Swagger UI |

## Run locally

You’ll need Docker with Compose v2 and OpenSSL. Run these commands from the repository root.

### 1. Configure the environment

Copy the [example environment file](.env.example) if you’re setting up the project for the first time.

```bash
if [ ! -e .env ]; then
  (umask 077 && cp .env.example .env)
fi
```

The example includes local PostgreSQL credentials. In your `.env`, replace `DJANGO_SECRET_KEY` and `MOCK_PAYMENT_SECRET` with separate values generated by `openssl rand -hex 32`. Keep your existing database credentials when using an initialized PostgreSQL volume.

| Setting | Purpose |
| --- | --- |
| `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` | Local database name and credentials. |
| `POSTGRES_HOST`, `POSTGRES_PORT` | Host-side database connection at `127.0.0.1:5433` by default. Compose uses `db:5432` for its services. |
| `PRODUCT_IMAGE_BASE_URL` | Base URL for product images. Use a URL that serves your registered image paths to display images. |
| `MOCK_PAYMENT_SECRET` | Signs and verifies mock payment callbacks. |
| `DJANGO_SECRET_KEY` | Signs Django data and JWT access tokens with the default settings. |
| `JWT_ACCESS_TOKEN_MINUTES` | Access token lifetime. The example sets it to `120` minutes. |
| `DJANGO_PORT` | Host port for the API. It defaults to `8001`. |

### 2. Start the services

```bash
docker compose up -d --build --wait
```

The web service applies database migrations when it starts. Compose also starts PostgreSQL and the reservation expiry worker.

### 3. Open the API

- [Swagger UI](http://127.0.0.1:8001/api/docs/) lets you browse and try operations.
- [OpenAPI JSON](http://127.0.0.1:8001/api/schema/) can be imported into API clients.
- [Django admin](http://127.0.0.1:8001/admin/) uses a local superuser account.

Swagger UI loads its pinned assets from jsDelivr. Django serves the OpenAPI JSON from the repository.

## Try a checkout

1. In Swagger, register a seller. Copy the seller’s `auth.access_token` into **Authorize**, then submit a shop application.
2. Create an administrator with `docker compose exec web python manage.py createsuperuser`. Sign in through the API, switch Swagger to the admin token, approve the shop, and create a category.
3. Switch to the seller token. Activate the shop, create an in-stock product, add an image path, and publish it.
4. Register a customer and switch to the customer token. Create a delivery address, add the product to the cart, and start checkout using that address ID.
5. Open the returned `payment_url` in your browser. Simulate a failure, retry checkout, and use the new link to simulate success. The order keeps its original reservation deadline.

## Tests and local operations

```bash
docker compose exec web python manage.py test
```

The test suite creates a temporary PostgreSQL database. The expiry worker checks for overdue reservations every 15 seconds. To run one sweep manually, use `docker compose exec web python manage.py expire_orders`.

Use `docker compose logs -f web checkout-expiry` to follow service logs. Use `docker compose down` to stop the stack. Local PostgreSQL data is stored in the `postgres_data` volume.
